Continue StudioFlow's Phase 1: add real database persistence. The project is a full-stack
"studio client workspace" (Express 5 API + React/Vite client) currently on `main` @ commit 7f4aa49.

STACK: pnpm workspace, TypeScript, Express 5, Drizzle ORM (postgres), Zod v4, Orval-generated
API client/zod from lib/api-spec/openapi.yaml. AI features run through an OpenAI-compatible
Gemini client (lib/llm.ts, lib/ai-generate.ts, lib/job-proposal.ts).

CURRENT STATE (all working, but everything is in-memory):
- API routes (artifacts/api-server/src/routes/studioflow.ts) read/write an in-memory
  `projects` array seeded in artifacts/api-server/src/lib/studioflow-data.ts. Restart = data loss.
- Proposal drafts/history are in-memory in artifacts/api-server/src/routes/job-proposals.ts.
- A Drizzle + node-postgres scaffold ALREADY exists but the schema is EMPTY:
  lib/db/src/index.ts exports `db` (drizzle(pool)) and `pool`; lib/db/src/schema/index.ts is empty.
  lib/db/drizzle.config.ts requires process.env.DATABASE_URL (postgres).
- `@workspace/db` is already a dependency of the api-server; `.replit` postMerge runs
  `pnpm --filter db push`.
